# 邗上课表 Web 版 · 课表导入方案设计文档

> 版本 v1.0 · 已定稿方案：**服务器代抓（方案一）+ 课表口令（方案四）**
> 前置条件：域名已完成 ICP 备案 ✅，需先为域名配置 HTTPS 证书（阿里云免费证书或 Let's Encrypt）。
> 本文档既是方案存档，也可直接按【第六章】拆成任务喂给 ZCode 施工。

---

## 一、背景与目标

- **Web 版定位**：邗上课表的 PWA 伴侣版，解决 iPhone 用户无法使用的问题。iPhone 用户用 Safari 打开网页 →"添加到主屏幕"→ 获得类 App 体验（iOS 16.4+ 支持系统级推送通知）。
- **核心矛盾**：网页无法像安卓 App 那样内嵌 WebView 登录教务系统抓课表（跨域限制 + 学校域名不可控），而**课表导入是本产品的灵魂功能，必须解决**。
- **选定方案**：
  - **方案一 · 服务器代抓**：用户输入学号密码，后端模拟登录教务系统代为抓取，体验最接近"一键导入"。
  - **方案四 · 课表口令**：安卓端用户导入后生成 6 位分享口令，其他同学（尤其 iPhone 用户）输入口令秒得同款班级课表。
- 两个方案共用同一个【导入预览确认页】，汇入同一份课表数据结构。

## 三、方案一 · 服务器代抓（完整逻辑）

### 3.1 用户侧流程

1. Web 版首页点「教务账号导入」。
2. 表单页：学号 + 统一身份认证密码，下方固定展示安全说明："密码仅用于本次登录抓取，**即用即焚，绝不存储**（该模块代码开源可查）"，须勾选同意才能提交。
3. 提交后进入加载页（前端轮询状态）。
4. 若学校系统要求验证码：页面弹出验证码图片，用户肉眼识别填入，继续。
5. 成功 → 跳转【导入预览确认页】，用户核对后保存。
6. 失败 → 按原因明确提示：密码错误 / 验证码错误 / 教务系统维护中 / 触发学校风控稍后再试，并提供"改用药丸口令导入"的退路指引。

### 3.2 后端抓取流程（技术步骤）

```
Step 1  GET webvpn 登录页 → 解析表单隐藏字段（execution 等）→ 保存会话 Cookie
Step 2  按登录页 JS 的加密逻辑加密密码（AES/RSA，具体算法以抓包为准，见 3.6 调研任务）
Step 3  POST 登录 → 若返回验证码挑战：状态置 NEED_CAPTCHA，验证码图片字节流代理给前端
Step 4  登录成功 → 持会话跳转教务系统学生端 → 请求课表页/课表接口
Step 5  用与安卓端完全相同的解析规则解析 → 统一课程模型 JSON
Step 6  立即销毁：清空密码变量 → 删除会话 Cookie →（可选）调用统一认证注销 → 返回结果
```

### 3.3 会话管理（即用即焚的核心实现）

- 每次代抓创建一个**一次性会话**：`session_id (uuid) → {httpx 会话 Cookie, 状态机, 创建时间}`，存内存字典或 Redis。
- **TTL 10 分钟**：无论成功失败，到期强制销毁。
- 抓取完成的瞬间立即销毁，不等 TTL。
- 密码只作为请求处理过程中的内存变量存在，函数返回前主动置空。

### 3.4 状态机与 API 设计

状态机：`LOGGING_IN → NEED_CAPTCHA → FETCHING → SUCCESS / FAILED(reason) → DESTROYED`

```
POST   /api/import/edu/session        创建代抓会话，提交 {student_id, password}
                                      返回 {session_id, status}
GET    /api/import/edu/captcha?sid=   获取验证码图片（image/jpeg 字节流）
POST   /api/import/edu/captcha        提交验证码 {session_id, captcha}
GET    /api/import/edu/result?sid=    前端每 1.5s 轮询，返回 {status, courses?, error?}
DELETE /api/import/edu/session        用户中途取消，立即销毁会话
```

- 抓取过程放后台异步任务（asyncio task / BackgroundTasks），接口立即返回，前端轮询。
- 所有接口仅接受 HTTPS + 已登录用户（复用现有 JWT）。

### 3.5 安全红线（逐条审计，写进代码注释）

1. 密码**绝不落库、绝不写日志**：全局 logger 对该接口请求体脱敏；FastAPI 异常处理器屏蔽该接口的请求体内容，防止密码出现在错误堆栈里。
2. 会话 Cookie 与内存中的密码，抓取结束（成功/失败/超时/取消）**四条路径全部确保销毁**——用 try/finally 兜底。
3. 限流：每用户 3 次/天，每 IP 20 次/天；连续失败 5 次锁定 30 分钟（防爆破学校账号，也防恶意刷接口导致服务器 IP 被学校封）。
4. 隐私政策新增条款，用大白话写明：我们代你登录教务系统抓课表，密码用完立即销毁、不做任何存储，代码开源可查证。
5. 代抓模块单独成目录 `server/app/edu_import/`，保持可独立开源。

### 3.6 开发前置调研任务（需你配合）

- 用电脑浏览器 F12 抓包一次完整登录过程，导出 HAR：确认 webvpn CAS 登录表单字段、密码加密方式（找登录页的 JS 加密函数）、验证码触发条件。
- 提供教务系统学生端课表页的准确 URL 和页面样本（你开发安卓端时已有，直接复用）。
- 提供一个可用于测试的真实账号（你自己的），配合开发期调试。

### 3.7 风控预案

- 请求特征模拟真实浏览器（UA、Referer、请求间隔随机 0.5~1.5 秒）。
- 监控代抓失败率：若短期失败率飙升（学校系统改版或风控升级），自动暂停该功能并在 Web 版公告"代抓暂不可用，请用药丸口令导入"，避免用户反复试错触发风控。

## 四、方案四 · 课表口令（完整逻辑）

### 4.1 用户侧流程

**分享方（安卓 App 或 Web 版均可）**：
课表页 →「分享给同学」→ 选择学期 → 生成 **6 位口令**（如 `K7M2QP`）+ 口令二维码 → 发群里。口令 7 天有效，可随时手动撤销。

**接收方（主要是 iPhone Web 版）**：
首页「输入课表口令」→ 输入 6 位码（或扫二维码直接带入）→ 预览课表 →「导入我的课表」→ 生成一份**属于自己的独立副本**，之后各自编辑互不影响。

### 4.2 数据模型

```
share_codes  口令表：
  id, code(6位,唯一索引), owner_user_id, semester_id,
  payload(课程快照JSON,已剔除分享者个人信息),
  created_at, expires_at, is_revoked, use_count
```

- 口令字符集：去除易混淆字符（0/O、1/I/L），30 个字符 → 30⁶ ≈ 7.3 亿空间。
- payload 生成时做**快照**：只含课程名/教师/教室/周次/节次，不含分享者账号、昵称等任何个人信息。

### 4.3 API 设计

```
POST   /api/share/create        生成口令 {semester_id} → {code, expires_at}
GET    /api/share/{code}        查看口令对应的课表预览（需登录，防爬虫枚举）
POST   /api/share/{code}/claim  领取为自己的课表副本 → 写入本人 schedules
DELETE /api/share/{code}        分享方撤销
```

- 防暴力枚举：查询接口每 IP 10 次/分钟限流；领取必须登录。
- `use_count` 每次领取 +1，分享方可以看到"已有 N 位同学使用"。

### 4.4 边界情况处理

| 情况 | 处理 |
|---|---|
| 口令过期/已撤销/不存在 | 友好提示"口令已失效，让同学重新分享一个吧" |
| 一口令多人领取 | 允许（全班场景正是如此），各得独立副本 |
| 分享方领完又改了课表 | 不影响已领取副本；分享页提示"课表有变动请重新生成口令" |
| 接收方该学期已有课表 | 弹确认："导入将覆盖你当前的 XX 学期课表" |
| 分享方撤销后再生成 | 生成全新口令，旧口令作废 |

## 五、前端改动清单

**Web 版（PWA）**：
1. 首页「导入课表」三个入口卡片：教务账号导入 / 输入课表口令 / 手动添加。
2. 教务账号导入页：学号密码表单 + 安全说明 + 验证码弹层 + 轮询加载态。
3. 口令输入页：6 位大输入框（自动大写、扫码带入）+ 预览 + 领取。
4. 复用现有【导入预览确认页】承接两种导入结果。
5. 「添加到主屏幕」图文引导（Safari 底部分享键 → 添加到主屏幕），并提示装到主屏幕才能开推送、数据才不会被清理。

**安卓 App**：
1. 课表页新增「分享给同学」按钮 → 调 `/api/share/create` → 展示口令 + 二维码 + 一键复制分享文案（"我的课表口令是 XXXXXX，打开邗上课表网页版输入就能用"）。

**官网**：功能介绍区更新——新增"网页版"介绍与三种导入方式说明，安全性对比表（重点突出"密码即用即焚"）。

## 六、开发任务拆解（按序施工，每阶段完成需验收）

- **阶段 W1 · 口令系统**：后端 share 模块全部接口 + 安卓端"分享给同学"按钮 + Web 版口令输入/预览/领取。（预计 1~2 天）
- **阶段 W2 · 代抓调研**：按 3.6 完成抓包调研，打通"模拟登录 webvpn → 拿到课表页"全流程脚本（先在命令行跑通，不接接口）。（预计 2~3 天，最难的一步）
- **阶段 W3 · 代抓接口与页面**：会话管理 + 状态机 + 五个接口 + Web 版导入页面 + 安全红线逐条落实。（预计 2 天）
- **阶段 W4 · 联调上线**：两方案端到端联调 + 安全审计 checklist 过一遍 + HTTPS 证书配置 + 官网上线。（预计 2 天）

## 七、验收标准（Definition of Done）

1. 安卓 App 导入课表 → 生成口令 → iPhone Safari 打开 Web 版输入口令 → 课表内容完全一致 → 双方各自修改互不影响。
2. iPhone Web 版输入学号密码 →（如有验证码则回填）→ 成功导入本人真实课表，课程名/教师/教室/周次/单双周全部正确。
3. **安全验收**：抓完一次课表后，在服务器数据库、Redis、日志文件中全文搜索该测试密码，搜索结果为零。
4. 口令过期、撤销、错误、覆盖确认四种提示均正确展示。
5. 代抓接口连续错误请求触发限流锁定；会话 10 分钟不操作自动销毁。
6. Web 版添加到 iPhone 主屏幕后：图标正常、全屏运行、（iOS 16.4+）推送授权弹窗正常。
