# 邗上课表手表版 · Xiaomi Watch S5 46mm 深度适配蓝图

> 2026-10-17 · 依据三处调研（米坛社区 S5 板块/产品百科、iot.mi.com Vela QuickApp 官方文档、doc.openvela.com 系统文档）整理。
> 本文是 UI/适配改造的动手前蓝图；每功能验证完再构建，构建后真机人工验收，不默认发版。

## 一、调研结论

### 1. 目标设备硬件（Xiaomi Watch S5 46mm）

| 项 | 值 | 来源 |
|---|---|---|
| 型号 | **M2530W1**（蓝牙版 / eSIM 版两 SKU） | 米坛产品百科 |
| 系统 | Xiaomi HyperOS（**Vela 5.0**） | 米坛产品百科 |
| SoC | 恒玄 **BES2800BP**（双 Cortex-M55 + BECO NPU + 2.5D GPU + BT 6.1/LE Audio；Wi-Fi 6 为芯片可选能力，是否装配随 SKU） | 米坛平台百科 |
| 存储 | 8.3MB SRAM + 64MB PSRAM + 4GB ROM | 米坛产品百科 |
| 屏幕 | **圆形 480×480**，DPR 2.0（PPI≈323） | 官方《多屏设计》设备表 |
| 对比旧目标机 | Redmi Watch 6 = M2523W1 / Vela 4.0 / BES2710IBP / 矩形屏 | 米坛产品百科 |

- 41mm 版（M2606W1）同 SoC、32MB RAM；分辨率官方表未单列，运行时自适应覆盖之。
- 快应用引擎在 S5 上可用（米坛 S5 板块大量第三方快应用：腕上浏览器/弦电子书/So词典/倒数日等）；侧载走第三方工具（表盘自定义工具 / AstroBox / Debug 模块），**不上架**，官方发布门槛不适用。

### 2. 系统与开发平台（Vela QuickApp）

- **适配技术栈**（官方《适配规范》）：Flex 自适应布局；px＝按 designWidth 等比缩放（类 rem）；`%`；`dp`（API 3+，密度无关）；媒体查询按形状；`device.getInfo()` 运行时取屏（screenWidth/Height、screenShape: rect|circle|pill-shaped、screenDensity、deviceType、apiLevel）。
- **弧形安全区**（官方《多屏设计》）：圆屏边缘裁切，主体功能必须落在安全区内；圆屏标题建议多行居中。
- **BLE**：`system.bluetooth.ble` 为中心模式（Scanner + GattClientDevice），与现行「手机 GATT Server ↔ 手表 read 分片」方案吻合，无需改协议。
- **无系统通知/推送 API**（features 全表无 notification/alarm）→ 到点提醒维持应用内定时器 + vibrate + Toast。
- **AIoT-IDE**：Windows 10+ 可用；无头构建走 npm `aiot-toolkit`（现行方案不变）；release 签名需 openssl 生成 `sign/private.pem`+`certificate.pem`。
- **openvela 原生路线（doc id=348 音乐播放器）**：NuttX + LVGL + Make/Kconfig，需整包源码编译固件（`build.sh vendor/openvela/...` + QEMU/adb），**第三方分发不可行**；仅用于理解系统形态（Vela＝NuttX+LVGL+miwear+快应用引擎）。手表版正确层级＝Vela JS 快应用，此结论不变。

### 3. 网络现实（跨两 SKU）

- 蓝牙版：三方快应用在 `bluetooth` 网络类型下**拿不到外网路由**（Redmi Watch 6 真机实测，平台限制；S5 同为 HyperOS 穿戴，预期同限制，待真机复测）。
- eSIM 版：可能有蜂窝/Wi-Fi 直连 → fetch 直连可用。
- **结论：双通道并存**——在线直连（配对码登录 / 分享码导入 / 同步）+ **BLE 离线导入课表**（第一公民）；网络提示按 `networkType` 动态引导（蓝牙网络时不再让用户「去连 WiFi」，而是引导走蓝牙导入）。

## 二、适配策略：单 rpk 通吃圆屏/矩形屏

1. **保持 `designWidth: "device-width"`**（px＝物理像素）：S5 323PPI 与 RW6 324PPI 同密度，字号物理尺寸不变；宽度差异由 flex/% 吸收。不引入双构建、不写死分辨率（延续既有决策）。
2. **形状感知三层**（全部走已在真机验证过的运行时 class 绑定机制，不依赖编译器对 `@media` 的支持）：
   - `app.ux` 运行时设备画像：screenWidth/Height/Shape/Density/model/product/apiLevel → `def.deviceProfile`；
   - `def.metrics()`：按形状输出页面几何（页边距/头部高/导航尺寸/卡片边距/键盘参数）；
   - 页面 `{{isRound ? 'xxx-round' : ''}}` class 变体 + 绑定 inline style 高宽。
3. **设备信息就绪同步**：`device.getInfo` 并入 `restoreSession` 的 Promise.all，`sessionReady` 即代表画像就绪——消除「页面 onInit 时 screenHeight 还是默认值」的竞态（旧代码默认 514，S5 实际 480，会裁掉底部导航）。

## 三、圆屏（480×480）几何规则

圆心 (240,240)、半径 240；y 处可用宽度 = 2·√(240² − (y−240)²)。据此：

| 区域 | 圆屏规则 | 矩形屏（保持现状） |
|---|---|---|
| 今日页头部 | 高 120px，**居中列布局**（周次/日期/学期/下一节四行居中），padding-top 34px | 高 118px，左右分布行 |
| 课程卡片 | 左右边距 36px（卡宽 408，全高安全），圆角 16px | 边距 24px，圆角 12px |
| 底部导航 | **悬浮胶囊**：宽 336px 居中、高 62px、圆角 31px，距底 70px（y=348..410，该处可用宽≥350）；容器高 132px | 通栏 84px 高 |
| 本周星期条 | 整条宽 320px 居中（顶部 y=0..64 可用宽≥326） | 通栏 |
| 登录数字键盘 | 键 84×50px、行距压紧，整体高度压进 y≤430 带内；下方「蓝牙导入」入口进滚动区 | 现状 112×64px |
| 导入字母键盘 | 行宽限 320px 居中、行高 46px、顶部内容压紧 | 现状通栏 46px 行 |
| 页边距 | 24px | 20px |
| 字号下限 | 全部 ≥18px（RW6 发虚教训沿用） | 同 |

- login / import 页内容整体包进 `<scroll>`，圆屏首屏之外的内容上滑可见，杜绝裁切死角。

## 四、数据 / 网络 / 提醒（不变项与修正项)

- 数据规则与手机 App 严格一致（weeks_type / custom_weeks / day_of_week / 12 节次两套作息 / 10 色盘）——不动。
- BLE 分片协议（`[seq][len][data≤180B]` + 0xFF 结束帧、Service 8F2A0001 / Char 8F2A0002）——不动，S5 BT 6.1 向下兼容。
- **api.js 收敛单域名** `https://hanshang.seanyan.store/yzu/api`：旧 IP `api.seanyan.store` 已于 2026-09-26 停机，http 明文逃生通道按安全要求移除。
- 提醒＝应用内定时器（无系统通知 API）；S5 后台保活待真机实测，不承诺。
- 性能纪律维持：logo 页零网络零延迟跳转、缓存秒开、页面销毁清定时器（BES2800BP 更强但不放松 FMP ≤2s）。
